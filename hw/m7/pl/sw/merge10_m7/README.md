# MERGE10 planner register header (REL0 snapshot)

`m7pl_planner_regs.h` here is the version MERGE10 (90795a3) generated for the m7 final config
(GMAP3 v9 planner export, 32-bit pointers, PATH_CTRL 0x90 / GMAP_OP 0x98).
The release keeps `hw/m7/pl/sw/m7pl_planner_regs.h` at the m5 version (1ff2bf9, export
hash d0233a56...) so that `m7pl_gen.py check` on the m5 configuration passes (CHECK PASS).
To build m7 with the GMAP3 planner, regenerate the header (`m7pl_gen.py planner-regs`) or copy
this file over the release header; MERGE10's own branch already has it in place.

## m7 whole-board build 63ba99b (REL9, 2026-11-04; the submitted whole board)

`m7pl_srch_regs.h` here is now the header generated by M7S17 (commit 63ba99b) from the search core v2 export
(`hw/srch_v2/`, SRCHK6 m17, sha256 10670556...). Register offsets are identical to the c8 header; only the source-hash
comment differs. Build impl-m6a-mk4-setp-m7s17-63ba99b: WNS +0.016 ns, WHS +0.009 ns, LUT 83,750, BUILD_ID 0x063ba99b,
app `m7_pl_m7s17`. Rebuild steps are as below with `SRCH_SHA256=10670556` and the search core v2 export; see
`bitstream_m7_fullboard/README.md` for the full command (including the place / phys_opt / route directives).

## m7 whole-board build 6661def (REL3, 2026-11-04; previous whole board)

`m7pl_srch_regs.h` here is the search-core register header generated by M7PRE0 (commit 6661def) from the
SRCHK5 c8i export (sha256 1338ebc4...). It is kept here, not in `hw/m7/pl/sw/`, for the same reason as the planner
header: the release's `hw/m7/pl/sw/` stays at the m5 configuration so `m7pl_gen.py check` on m5 passes.

To rebuild the m7 whole board (build impl-m6a-mk4-m7pre0-6661def: WNS +0.022 ns, WHS +0.007 ns, LUT 89,426,
BUILD_ID 0x06661def), first copy both headers back:

    cp hw/m7/pl/sw/merge10_m7/m7pl_planner_regs.h hw/m7/pl/sw/merge10_m7/m7pl_srch_regs.h hw/m7/pl/sw/

then run the MERGE10 one-command script `scripts/build/launch_whole_m7.sh` (export only; in the run tree
`MERGE10/tools/launch_whole_m7.sh`) with planner = GMAP3 v9 (480886f6), srch = SRCHK5 c8 (1338ebc4),
memk = MEMK4 (8e9daf92), obs empty:

    LPD_FIFO_NEW=1 PLANNER_SHA256=480886f6 SRCH_SHA256=1338ebc4 MEMK_SHA256=8e9daf92 \
    bash scripts/build/launch_whole_m7.sh <tag> <GMAP3 ooc_v9 export.zip> <SRCHK5 c8i export.zip> <MEMK4 core2 export.zip> ""

(MEMK_IF is taken from the memk IP -> bram; strategy c1; 166.67 MHz clk1.) Package with
`hw/m7/pl/tools/package_app.sh <build> <ip_repo> <out> m7_pl_m7pre0c1`. The headers only affect the driver and
the package self-check, not the bitstream.
