# Design Layout（2022.2 版）

管理一个 HLS 设计在架构流程各阶段的规范目录。由 `reference/architect.md` 调用（Step 2d "Write to rearchitect"），
除非检查或修复工作区，不单独运行。

**运行位置**：在 hlsopt 实验区 worktree 里（`reference/architect.md` 在写产物前已按
`session/hlsopt_session.sh start --allow-new ...` 建好实验区并 `cd` 进去）。不要在用户的工作副本或 `main` 上建目录。

---

## 规范目录树

```
design_name/
├── frame_based/          ← 输入（用户给的、未改写的 C++ 参考实现 + testbench）
│   ├── kernel.cpp
│   └── testbench.cpp
└── rearchitect/
    ├── v1/               ← V1：第一版架构（architect 生成）
    │   ├── src/          ← kernel_hls.cpp
    │   ├── tb/           ← testbench.cpp（从 frame_based/ 原样复制）
    │   └── run_hls.tcl   ← 2022.2 Tcl 工程脚本（取代上游的 cfg + component json）
    └── v2/               ← V2：备选架构（可选，architect 明确生成时才有）
        ├── src/
        ├── tb/
        └── run_hls.tcl
```

`design_name` = 工作区根名（从源文件名派生，或用户指定）。运行 `scripts/hls_run.sh` 后，`run_hls.tcl` 里
`open_project` 指定的工程目录（`<design_name>_prj/`，含 `hls.app` 与 solution 目录）会出现在版本目录下；它是生成物，不入库。

---

## 阶段定义

| `stage` 参数 | 建的目录 | 额外写入的文件 |
|---|---|---|
| `rearchitect_v1` | `design_name/rearchitect/v1/src/`<br>`design_name/rearchitect/v1/tb/` | `design_name/rearchitect/v1/run_hls.tcl` 模板 |
| `rearchitect_v2` | `design_name/rearchitect/v2/src/`<br>`design_name/rearchitect/v2/tb/` | `design_name/rearchitect/v2/run_hls.tcl` 模板 |
| `show` | 不建任何东西 | 打印期望的目录树 |

---

## 行为

### 任意阶段（`show` 除外）

1. 从调用方上下文拿到 `design_name` 与 `stage`。
2. 在上表查阶段。
3. 建目录：
   ```bash
   mkdir -p <path>
   ```
4. 在版本根写 `run_hls.tcl` 模板（占位符由调用方 `reference/architect.md` 写完后立即填）：

   ```tcl
   # Generated by design-layout (fpga-hls, Vitis HLS 2022.2) — fill in <TOP_FUNCTION>, <XPART>, <CLOCK_NS>
   open_project -reset <design_name>_prj
   set_top <TOP_FUNCTION>
   add_files src/kernel_hls.cpp
   add_files -tb tb/testbench.cpp
   open_solution -reset solution -flow_target vivado
   set_part <XPART>                        ;# KV260: xck26-sfvc784-2LV-c
   create_clock -period <CLOCK_NS> -name default
   # 可选：让写错的 pragma 直接报错，而不是 WARNING 后被丢弃（2022.2 有此选项）
   # config_compile -pragma_strict_mode=true
   ```

   - 器件写在 `set_part`，时钟周期（ns）写在 `create_clock -period`；不要发明别的写法。
   - 流程命令（`csim_design` / `csynth_design` / `cosim_design` / `export_design`）不写进模板，由
     `scripts/hls_run.sh <proj_dir> <solution> <step>... --tcl run_hls.tcl` 按 step 执行（见 `reference/run-flow.md` §2）。
   - testbench 用 OpenCV 时的 `-cflags` / `-ldflags` 写法见 `reference/architect.md` Step 2d。

5. 打印确认，例如 `rearchitect_v1`：
   ```
   [design-layout] Created design_name/rearchitect/v1/
     ├── src/          ← write kernel source here
     ├── tb/           ← write testbench here
     └── run_hls.tcl   ← fill in TOP_FUNCTION, XPART, CLOCK_NS
   ```
6. 把建好的阶段根路径返回给调用方。

### `stage=show`

只打印，不建任何东西：

```
[design-layout] Workspace for design_name (architect stages):
design_name/
├── frame_based/     ← INPUT (assumed to exist)
└── rearchitect/
    ├── v1/  → src/  tb/  run_hls.tcl
    └── v2/  → src/  tb/  run_hls.tcl   (created only if V2 is applicable)
```

## 规则

- **不在 `design_name/` 之外建目录**；不在实验区 worktree 之外建目录。
- **不覆盖已存在的目录**：目录已存在就打印警告并跳过，不删除已有内容。
- **V2 = N/A 时不建 `rearchitect/v2/`**：architect 必须显式调用本文件；没有调用即表示没有 V2。
- **`run_hls.tcl` 是模板**：总是先用 `<PLACEHOLDER>` 写出，调用方随即填入实际值。
- **2022.2 禁止生成**：Unified IDE 的 cfg / component json 文件、`vitis-run` 或 `v++ --mode hls` 命令行（2022.2 不存在）。
- 新建的文件（`src/kernel_hls.cpp`、`tb/testbench.cpp`、`run_hls.tcl`）要在 `session/hlsopt_session.sh start --allow-new --files "..."`
  里事先列出：会话脚本只提交 `--files` 列出的文件，未列出的文件**不会报错、只是不进任何提交**，回退与收尾时也不会被带上。
  首次提交由 `hlsopt_session.sh baseline` 完成；不要自己 `git add -A`。
