# 验收清单（主控对每个交回的包过一遍）

1. **数字自己复核，不采信自报。** 关键数字用同一套工具从代理的最终标签重跑（例：git archive 到全新目录重跑 csim / csynth / cosim）。
2. **门是测量前写的吗？** 对照任务书里的门；代理事后改了门或口径 ⇒ 退回。
3. **正确性有阳性对照吗？** "一致 / 没影响 / 0 条"类结论，必须有一个必然会改变输出的对照证明检查方法本身有判别力。
4. **口径标清了吗？** 估计（如 HLS csynth）和实测（如 OOC、板上）不能混用、不能相减。
5. **锁定文件没动吗？** 测试台、golden、构建脚本等不允许改的文件，用 diff 对基线确认。
6. **有坏处的选项写了坏处吗？** 降档 / 跳过 / 复用旧结果，必须写清损失和它不解决的根因。
7. **未完成项列了吗？** 没测的写"没测"，不写"应该没问题"。
8. **上下文用量**：代理已过交接线还在干活 ⇒ 令其写 HANDOVER 收尾，下一棒新开，不续旧代理。
