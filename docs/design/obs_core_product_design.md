# 观测与核验核：产品工作负载修订v4，复审通过、实施中


- 产品相机彩色640×480，深度由相机硬件对齐到彩色；每帧固定19个证据框＋本帧全部观测，实际最多10条观测，**全部处理及内存等待合计≤10ms**。
- 现有640×360材料按480/360行数做设计折算；折算是预测，不能改写成真实480图像/位姿或RTL结果。
- 接口最大1280×800、32框满覆盖仅要求正确，可以更慢；不为这类输入增添计数引擎或片上存储。README单列该口径的拍数。


## 1. 产品框数来源与设计输入


只读提取其中两帧10观测的原日志：一帧11个输入检测框，一帧10个。核必须包含被判拒框的开销，不能只处理成功输出10条。原框面积和25612/26281像素；按原半开框两个y端点分别floor(4y0/3)/ceil(4y1/3)，480行规划包络面积和34472/35266。原日志此处没有分辨率字段，这些是按owner要求的规划折算，不能称已采到480深度样本。

该包络保留每个输入框，不伪造、复制10个大框来制造最坏条件，也不因框数较多就丢框。不同日志帧的深度/掩码尚未测，本轮只读几何元数据。

## 2. 19框只用三个有效时隙，不增加引擎

仍8引擎，不改32框接口。每批锁存 `S=max(3,ceil(B/8))`：1..24框用3时隙，25..32框用4。2位phase显式比较回绕，不做除3；启用/关闭框的原输出语义不变。

good-5实际RTL曾读counts于迭代i+2、写于i+4。S=3时下一同址读为i+5，位于前写后一拍；S=2则同拍RAW，因此禁止降至1/2。新实现必须重新检查实际读写沿、II1、全局stall同步冻结和批次flush，真实依赖distance≥3，不能用false依赖。旧RTL通过不能证明新调度通过。

结合v3紧凑token，产品19框的每次有效命中服务由4拍改3拍，未访问第4slot但物理存储保留支持32框。此处是低资源优化，不是为接口极端提高并行度。

## 3. CDF用三条共享lane，固定开销按11输入重算

三world银行同时读同一地址循环，三lane各保留自己的累计数/有序rank游标；HSV阶段复用这三lane读H/S/V银行。每lane一个累加器、一个比较器，遇本bin跨多个rank时保持bin并逐个记录，最多增加少量捕获拍；不复制18个宽比较阵列。

每框coarse256＋HSV256＋fine最多1536扫描拍，合计2048；三world银行并行清零256＋1536=1792拍，HSV可和coarse清零并行。11候选框约42240拍，加depth hist/cover、mode、参数和结果控制，统一分配60000拍。若实现仍是旧单lane串行扫描，就不能使用这个预算。

存储沿用v3工作预测23.5BRAMeq/10URAM、含余量24/10。新增CDF控制约200～350LUT是人工预测，必须和CSR/配置瘦身一起以整IP OOC核对；未把增加DSP或银行数量说成面积已达标。原证据实际4128LUT仍需压到≤3000的目标。

## 4. 640×480整帧预算：大框与多框各一类


大框用既有slot33全帧4输入，3个需要后处理，480包络后处理面积96296；多框用实际11输入/10输出那一帧，保守把11个全部列入后处理，面积34472。它们是两类规划输入，后者没有配套本轮实际D16，不能将下表冒称实车结果。

| 整帧分项，100MHz拍 | 480行大框(slot33) | 480行多框(11输入) |
|---|---:|---:|
| 首遍共享读图/证据/hist排队，无额外AXI等待 | 347385 | 270031 |
| 全部run CCL/parent/label预算 | 200000 | 200000 |
| coarse/HSV＋fine并行投影 | 216666 | 77562 |
| 参数/清零/CDF/结果/灌排 | 60000 | 60000 |
| 所有额外AXI等待/对齐/短burst/反压/写响应 | 125000 | 125000 |
| **整帧预算** | **949051** | **732593** |
| **时间预算** | **9.49051ms** | **7.32593ms** |

200000拍CCL和125000拍等待是实现上限配额，尚未实测证明；超出即失败，不排除IO后重新报10ms。CCL原两360行数值关键对照不重跑，480这里只作行数与几何预算；640×360固定236对仍用于数值门，实际产品640×480实测由后续整核/集成验证补足。任何软件参数准备/驱动耗时与核AP_START到两支结果写响应完成/done应分别报告，不混成整机加速比。

原v3的9.29/9.52ms是360行/原框数预算，不能再用于产品达标结论。本稿不是将该数字简单乘4/3后挑较小数，而是显式改3时隙、计入11输入固定开销并重新排队。

## 5. 最大接口正确性：保留慢路径，不拿片上容量拒出

证据1280×800、32满覆盖仍用4时隙。全有效满覆盖的计数主体4096000拍=40.96ms，另加参数/覆盖表/比值/写回及AXI等待。这不是整核最终实测上限。

观测原片上单框65536像素/32768标签是快速工作区容量，**不能拿它宣称满幅1024000像素观测已正确**。最大输入需精确DDR慢路径，逐框串行，复用同一数值ALU/坐标/颜色通路，不增加片上整帧cache，不截断框或连通域：

| DDR scratch区（单框复用） | 最大布局 |
|---|---|
| label_plane | 1024000×u32，4096000B，背景0/正标签 |
| parent/area/rank | 256000×u64，2048000B；parent18+area20+rank5，余位保留 |
| depth/world/HSV hist及小状态 | 32768B；计数u32，精确值最大1024000 |
| **最小scratch长度** | **6176768B**，64字节对齐 |

标签数界为ceil(W/2)×ceil(H/2)，最大640×400=256000；18位0基parent及正label可表示。parent/rank最终可复用rank位存isMax，光栅首像素并列规则不变。所有有效数/面积用20位或更宽，累计全批面积32×1024000=32768000用至少25位，不用原17位或131072全帧cache容量拒绝这些输入。

启动时先校验所有框面积：只要任一观测框超过65536，观测整批在首遍前选择DDR慢模式，首遍只做证据，之后观测逐框重读建20位/u32 hist；不能先用17位fast hist计到溢出才切模式。删除原131072的全帧cache容量拒绝，因为本版没有该cache；batch面积按25位累计。

慢路径由有界FSM发出单字/连续burst事务：读parent记录→等待返回→比较/压缩/合并→写回→等响应；不递归、不断言虚假II。父表/标签/大计数放DDR，数值质量门和精确阈值不变。现唯一gmem读写通路在快/慢阶段互斥复用，新增请求仲裁/地址范围校验；不得为慢模式另复制一个完整AXI master并漏算面积。LUT开销须纳入4500，不能因片上表不增就声称资源不变。


对32框均满幅，总观测像素P=32768000；拍数应写成首遍＋逐框CCL/父表访问＋分位/HSV遍历＋全部DDR事务等待。CCL和内存访问数据相关，不能仅给一个面积比例就称精确上限；最终README须列实测输入/条件和实际周期。
