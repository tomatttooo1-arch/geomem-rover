### 2. 跟踪器重新预注册（`prereg/`）

仪器先校准（开跑前，在旧调参集上）：C++ 仿真器原型参数下复现 CTRLPS0 的 `sim_result.json` 与 `diag_adaptive.json`，四位小数全同，
一组原本不过（16 次违例）、一组原本过（0 次），两种结局都复现。aarch64 下的同一判定运行与 x86 输出逐字节相同。

判定运行（`--mode track --product 1`，即产品跟踪器＋限幅＋足迹检查；129 = 127 个独立用例＋2 条合成）：

| 判据（门槛） | 第 1 档（原始台阶） | 第 2 档（平滑，产品默认） |
|---|---|---|
| 到达率 30 ms（100%） | 129/129 过 | 129/129 过 |
| 横向偏差 p95（≤ 0.05 m） | **0.0506 不过** | 0.0282 过 |
| 横向偏差最大（≤ 0.10 m） | 0.0901 过 | 0.0671 过 |
| 车心进 ≥253 格（0 次） | **65 个采样点，用例 099–102，不过** | **29 个采样点，同 4 例，不过** |
| 原地转 \|ω\|（≥ 0.10） | 最小 0.12 过 | 最小 0.12 过 |
| 100 ms 到达率（≥ 95%） | 129/129 过 | 129/129 过 |

**判定：不过。** 判据没动。区分实验（`diag/`，均在同一 car1015 集上，属事后诊断）：

- **违例全是未知格**：4 个用例的全部违例采样点都落在同一个代价 255 的格上，没有一次进 253/254。该格斜贴着路径拐角（路径拐点 (35,25)，未知格 (34,24)），
- 竞争解释与区分：
  - 「贴近检测没触发、用了长前视」：违例时刻全部处于贴近模式（前视 0.15 m）→ **排除**。
  - 「时延/动力学过冲」：100 ms 与 30 ms 违例数相同（65 对 65）→ **排除为主因**。
  - 「产品件（限幅、爬行）造成」：关掉限幅违例数不变（65）；关掉爬行降到 26/8，但仍是同 4 例——爬行让车在格里待得更久、采样点变多，不制造新违例。
  - 「纯追踪切角」：缩贴近前视有剂量关系——0.15 m：65/29，0.10 m：51/0，0.05 m：0/0（第 1 档/第 2 档）。**支持**。
  - 阳性对照：前视 1.0 m 时 171 个违例、13 个用例、p95 0.113 m——仪器看得出切角。
- **第 1 档 p95 0.0506** 来自开阔处的台阶路径（前视 0.30–0.45 m），不是贴近处：贴近前视缩到 0.05 m 时 p95 仍是 0.0505；41/129 个用例自身 p95 > 0.05（最高 0.073，用例 108–113）。
  同一个候选在它自己的调参集上 p95 也是 0.0509（设计里写成「0.051」），本来就在门槛上方。第 2 档（产品实际跟的平滑路径）p95 0.028。
- 结论（措辞按证据等级）：与「纯追踪在贴着未知格的拐角处切角约 3–4 cm」一致，剂量实验支持；坐实需要在新数据上预注册一个修正后复测。

同判据只报告（`--mode core`，完整 NavCore 闭环）：30 ms 与 100 ms 都是 129/129 到达、p95 0.024、最大 0.059/0.053 m、进 ≥253 格 0 次、原地转最小 0.12、误拦 0。
在 099–102 上没违例，是因为每 0.5 s 从车当前格重规划＋平滑后的路径不再贴那个拐角——这是一组好的旁证，但它不是判定口径，也不是新数据。

## 给 N2（CTRLPS2）的接口

构建：`cd tools/kv_nav && make host`（板上原生 g++ 同样可用，或 `make aarch64` 交叉）。产物 `build/<arch>/libkv_nav.so`。**必须带 `-ffp-contract=off`**（Makefile 已带），否则 aarch64 会融合乘加、取路/平滑不再逐字节。

C 接口（`kv_nav_c.cpp`，一个句柄一个导航实例，单线程调用）：

| 函数 | 用途 / 频率 |
|---|---|
| `void* kv_nav_create()` / `kv_nav_destroy(h)` | 生命周期 |
| `int kv_nav_set_param(h, "name", value)` | 按 `Params` 字段名设参数（未知名返回 −1）；开目标前设 |
| `kv_nav_set_goal(h, id, x_map, y_map, yaw_map, t)` | NAV_GOAL；目标在 **map 系** |
| `kv_nav_cancel(h, t)` | NAV_CANCEL → 状态 CANCELED、零命令 |
| `kv_nav_set_map_to_odom(h, x, y, yaw)` | 每次 NAV_ODOM 带来的 map→odom；每拍按最新值把目标换到 odom 系，跳 > 0.3 m 立即重规划 |
| `kv_nav_update_costmap(h, grid6400, base_x, base_y, stamp)` | B1 膨胀平面（Nav2 语义，行优先 [y][x]），odom 格基点，时间戳与 tick 同一时钟；**> 1 s 旧的图不规划，车原地等** |
| `kv_nav_set_global_route(h, xy_map, n)` | G1 全局路线（map 系米，交错 x,y）；n=0 清空。目标出窗时取路线首次出窗点；无路线时用车→目标直线 |
| `kv_nav_tick(h, t, x, y, yaw, v, w, permit, teleop, &cmd)` | 20 Hz；位姿为 odom→base_link；`permit=0` 或 `teleop=1` 时进 PAUSED、零命令、不计卡住，放开后从规划重来 |
| `kv_nav_get_path(h, xy, cap)` | 当前跟踪路径（odom 米），给 NAV_CMD 的路径摘要/可视化 |

`kv_nav_cmd` 字段：`v, w`（下发）、`state`（0 IDLE、1 PLANNING、2 ROTATE_TO_PATH、3 TRACK、4 FINAL_ROTATE、5 SUCCEEDED、6 RECOVER_WAIT、7 RECOVER_OBSERVE、8 PAUSED、9 ABORTED、10 CANCELED）、
映射到 NavigateToPose：SUCCEEDED → 成功；ABORTED → 失败（reason 作原因码）；CANCELED → 取消；其余为进行中（反馈用 `remaining_m`、`recoveries`）。
`kv_nav_state_name/reason_name` 给日志用。库内没有时钟、线程、I/O；**链路断开后的 150 ms 归零由 proxy 负责**，库不管。

给 N4：板上 `make aarch64` 或原生 `make host`，跑 `build/*/test_planner_golden <vectors> <cases>`、`test_state_machine`、`kv_nav_bench <cases>`（cases 用 `sim/prep_car1015.py` 生成）。
PL 核到位后：写 `PlFieldFn` 驱动，`backend=1`，先 `selfcheck_every=1` 跑一遍向量，确认 0 次不一致再放到 20。
