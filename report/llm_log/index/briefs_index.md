# 任务书总索引（主控派给执行代理的全部任务书）

本表由 `build_briefs_index.py` 从运行目录逐个任务书自动生成，未手改。每个任务书是主控会话写给一个执行代理（子代理）的完整提示词；同一个包的接力棒（`_b`、`_c`、`_r2` 等后缀）各占一行。"结果"取自同目录 README.md 或 HANDOVER.md 的结论段第一句；"主控验收"取自主控日志 CONTROL.md 中该包名之后的判词（收 / 不收或打回 / 改判 / 轮换，轮换指代理上下文用满后换新代理接力）。已脱敏：人名改为 member-a/b/c，绝对路径改为 `<run>`、`<repo>` 等占位符。

## 统计

- 任务书总数：**111** 份，分属 **100** 个工作包（其余为同包接力棒）。
- 按类型（以包计）：HLS 核 24；整板构建 13；上板测量 15；文档 14；发布 4；产品软件/链路 30。
- 主控日志里出现过“不收 / 打回 / 改判”的包：**5** 个（MEMK3, MERGE9P, NN-CAM2, SRCHK4, SRCHK5）。
  - 人工复核（2026-11-04，逐条读主控日志原句）：真正被判"不收"的是 3 个——MEMK3（功能收、面积不收，随后派 MEMK4 重写架构）、SRCHK4（LUT 门没过，不收）、SRCHK5（不收面积、只收功能版）；MERGE9P 是"收（部分）"，同一条里主控因推算方法失效改了判据，并打回的是另一成员的存储设计而非本包；NN-CAM2 的"改判"是把它从可选项改判为文档必需的数据项，不是否定。
- 主控日志里出现过“轮换”的包：24 个；主控日志中没有找到判词的包：26 个（多为小包或仍在进行中）。
- 类型按包名前缀归类：HLS 核＝单个 PL 加速核的设计与实现；整板构建＝Vivado 整板集成与比特流；上板测量＝在板子上跑测量或冒烟；文档＝设计报告与提交材料；发布＝提交代码包与发布标签；产品软件/链路＝PS/Nano 侧软件与产品链接入。
