# 案例 1：语义记忆核面积超预算 3.7 倍 → 改成"共用运算单元＋微程序顺序器"

> 摘录均出自原始记录，`……` 表示删节；路径、人名已按 README 的脱敏规则替换。

## 1. 提示词摘录（任务书 MEMK3/brief.md，主会话写给执行代理）

> 3. csynth：逐函数对手算（去掉 m_axi 900、加 LUTRAM 约 400），任何一项超手算 1.5 倍先改再往下。
> ……
> 5. 一次 OOC  at 100 MHz：**LUT ≤2,500、RAMB36 当量 ≤6、URAM ≤2**、WNS ≥0。压不到先回报，不擅自把逐槽计算挪回 PS。

（全文见 `briefs/memk3_brief.md`；上一阶段设计任务书见 `briefs/memk0_brief.md`。）

## 2. 模型回答摘录（MEMK3/README.md "结论"节）

> 1. **LUT 压不到 2,500。按任务书停在这里回报，没有把任何逐槽计算挪回 PS。**
>    一次 OOC（100 MHz，Vivado 默认策略……）的实测是：**LUT 9,180**，FF 9,041，DSP 55，
>    BRAM 10 个 RAMB18（即 5 个 RAMB36 当量），URAM 2，布线后周期 9.077 ns（WNS +0.92 ns）。
>    存储……和时序……都达标，只有 LUT 是预算的 3.7 倍。
> 2. **超出的原因是结构问题，不是位宽问题。** HLS 给源码里的每一个加法、比较、选择都单独造一份硬件，
>    这个核的 C 代码里有约 560 个这样的运算。我做了一轮把 64 位整数收窄到实际位宽的修改（i64 从 69 处降到 24 处），
>    csynth 估计只从 18,115 降到 17,963（−0.8%），说明问题不在位宽。另外，AXI-Lite 数组外壳本身就占了 1,418 LUT，
>    设计手算时只给了 150。想做到 2,500，数据通路得改成分时复用，也就是一个共用的运算单元按微程序一步步算……
>    这一步要重写整个核，需要主控来定。

## 3. 纠错过程

**发现问题。** 设计阶段的手算预算是 2,500 LUT，实测 9,180。执行代理没有自行降级（例如把计算挪回 PS），而是按任务书停下回报，并给出一个区分性实验：把位宽收窄一轮，LUT 只降 0.8%，从而排除"位宽太宽"这一解释，指向"每个 C 运算一份硬件"的结构性原因。

**主会话验收与裁定（CONTROL.md 原文）：**

> 11-04 10:0x **MEMK3 交回 → 功能收、面积不收。** export 90a86fc9（判据① D1prod/D2/D3 过、两阳性对照抓到；联仿 531 次逐字节同；WNS +0.92；5 BRAM36/2 URAM）；OOC 9,180 LUT 对预算 2,500（3.7 倍），结构性（每运算一份硬件、AXI-Lite 数组外壳 1,418、LUTRAM 写口 1,427），收窄位宽只降 0.8%。……**裁定：**①走路线 A（共用运算单元＋微程序 ROM＋顺序器）并入 C 的便宜部分，派 MEMK4；……

> 11-04 10:0x **派 MEMK4（worker-opus-high，effort high）**——理由：微程序化架构设计属难题分析（指令集、寄存器堆、各引擎映射与手算预算），上一棒正是设计层估算失准。

**改法写进下一份任务书（MEMK4/brief.md）：**

> ## 主控裁定（已定，不再讨论）
> - 走路线 A：一个共用运算单元（加减、比较、乘，宽运算放 DSP）＋小寄存器堆（LUTRAM 或 BRAM）＋微程序 ROM……用 Python 生成器从一份可读的操作表生成 ROM 初值，并把同一操作表在 Python 里解释执行作为参考，与 C 模型逐位对照……
> ……
> 1. 先出架构设计 `RUN/MEMK4/ARCH.md`……逐部件手算 LUT/FF/DSP/BRAM。手算合计必须 ≤2,500 再往下写码。

同时，主会话把这次教训写进了所有核共用的硬件设计规矩（HWDESIGN_RULES 末节"HLS 写码五条"：常量用 ROM、同一存储只留一个读调用点、输出多路选择用相位计数器、最小位宽、csynth 后逐项对手算），后续各核的任务书都引用它。

## 4. 最终结果（MEMK4/README.md 结论节；CONTROL.md 11:4x 验收行）

> 1. **LUT 压到了 1,487（OOC 实测），在 2,500 的门以内。** MEMK3 是 9,180，降了 84%。
>    FF 909、DSP 4、RAMB36 4、URAM 2，布线后周期 8.0 ns（100 MHz 下 WNS +2.0 ns）。
> 2. **功能和 MEMK3 的 C 模型逐位相同。** 14,886 次录制调用……结果块逐字相同；联仿 531 次调用逐字节相同……
> 3. **拍数满足"典型帧 ≤1 ms"。** 实车 D2 每帧中位约 0.42 ms、最坏约 0.81 ms……

| 版本 | 架构 | OOC LUT | FF | DSP | 功能校验 |
|---|---|---|---|---|---|
| MEMK3 | HLS 直译（每运算一份硬件） | 9,180 | 9,041 | 55 | 14,886 次调用逐字同 |
| MEMK4 | 共用运算单元＋微程序 | **1,487（−84%）** | 909 | 4 | 同上＋联仿 531 次逐字节同＋阳性对照 |
