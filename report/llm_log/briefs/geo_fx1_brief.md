# GEO_FX1：几何核定点版 HLS 实现（第二阶段）

**范围：只在宿主上做，不碰板子。**

## 背景

FPGA 国赛线做的是 KV260 加 Jetson Orin Nano 的寻物小车。几何核里的换算级目前是浮点设计，占 11,903 LUT、136 DSP。第一阶段已经把它重新设计成定点版，设计已由主控审过并批准，本包按这份设计去实现。

第一阶段留下的材料：
- 设计书：`<run>/GEO_FX0/DESIGN.md`。开工前通读，重点看 §2、§3、§4、§5。
- 定点黄金模型：`GEO_FX0/tools/fx_golden.cpp`。
- 判门脚本：`GEO_FX0/tools/gates.py`、`downstream.py`、`stats_check.py`。
- 第一阶段的代码在分支 `feat/member-a/nat-geofx0-20261103`，worktree 是 `<worktree>/nat-geofx0-20261103`。现行几何核的 HLS 源码也在那棵树里。

owner 有一条硬规矩：硬件设计没写好、没审过，就不能直接拿 HLS 转代码。本包的设计就是 GEO_FX0/DESIGN.md。电路的级划分、位宽和 DSP 映射都按设计 §2 写；如果和设计不一致，要写出不一致在哪里、为什么。

## 主控对第一阶段的裁定

1. **只留 16 位深度码这一路输入（§3.1 C 项）。** 原来的寄存器偏移不挪位置、只往后加；旧端口保留，但核不再读它。PS 驱动和 kv_server 的改动留到第三阶段，本包只做核。
2. **深度 CRC 用 §3.4 的方案**：保留浮点 CRC，用一个专用的"码 × 单位"精确乘法器来算。这样 Nano 侧一行都不用改。
3. **§4 里标了"做"的 A、B、C、D、E、F 都做。** 行走窄化 W1 单独做成第二步，单独提交、单独打标签，确保能单独回退。W2、W3、G、H 不做。
4. **深度前端统计（§3.3）**：4 个只读寄存器在核里做出来。Nano 侧什么时候改成读这几个寄存器，等 NANOSW0 的实测结果出来再定，不在本包范围内。
5. **rec30 上质量门没过的问题，由 owner 决定。** 第一阶段的诊断显示：定点网格与真值网格逐格相同，没过的原因是浮点参考自身的舍入。因为设计不会因为这件事而改，主控决定本包并行开工。

   **第 0 步，最先做：用独立的方法复核真值臂。**
   - 第一阶段的真值臂是用 long double 写在 `fx_golden.cpp` 里的。这一步换一套独立实现：用 Python `fractions.Fraction` 做精确有理数运算，直接从原始输入出发，按参考的实数公式算端点体素，不调用 `fx_golden` 的任何代码。
   - 把 rec30 上端点体素与参考不同的那些射线全部算一遍，至少也要随机抽 2 万条，外加全部 12 个"漏检"占据格对应的射线。
   - 比较这套精确值与定点版、与参考是否同格。
   - 预期是精确值与定点版同格。**如果有任何一条精确值与参考同格、却与定点版不同格，立刻停下，向主控报告**，不要继续往下做。
   - 这是对一个有利于我们的修正所做的对立审核，所以必须做，但只做这一项。

## 我们想要的结果

- **HLS 定点几何核一份**，满足：
  - 时钟按 m4 几何核现在的口径：clk_pl_1 166.67 MHz，OOC 用 6 ns 约束；
  - II=1，每拍一个像素；
  - csim 输出与 `fx_golden` **逐位一致**，数据用 rec30 和 car570，射线抽稀打开；
  - 不需要再和旧的浮点参考逐位一致。旧参考只作为质量门的对照，第一阶段已经做过了。
- **一张 OOC 实测的资源与时序表**，和设计 §5.2 的推断逐项对照。目标是整核 LUT 约 13k、W1 之后约 12.3k，DSP 约 18。偏差大的地方写出原因，能继续压就继续压。
- **联仿 2 帧**：读实际拍数，与 §5.3 的预期对照。
- **寄存器表**：新增寄存器的最终偏移，为第三阶段改驱动做准备。
- 第 0 步的结论：精确复核结果，写一段话。
