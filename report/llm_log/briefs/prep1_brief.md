FPGA 国赛线（KV260 + Jetson Orin Nano 寻物小车）。识别前处理核的作用是把彩色帧变成 DPU 输入张量：缩放、灰边、量化。这个核的硬件设计已经做完，并已经过主控审核：

`<run>/PREP0/DESIGN.md`

**开工前通读这份设计，尤其是 §1.2、§2 和 §3.2。** 除此之外还有两样现成的东西：
- 定点 C 行为模型 `PREP0/model/prep_model.c`。它按硬件结构写成，在 198 组、1.6 亿字节上与参考实现 0 字节差。
- 核对脚本 `PREP0/model/check_model.py`。

owner 有一条硬规矩：不允许不做硬件设计，直接把软件代码交给 HLS 转成电路。本包的硬件设计就是 PREP0/DESIGN.md。

**HLS 只是用来实现这份设计的语言。** 电路的级划分、位宽、存储和流水都照设计 §2 来写，不要拿参考 Python 或 cv2 的写法改一改就交给 HLS。和设计不同的地方都要写出来，说明为什么改。

## 主控审稿意见（照此执行）

1. **范围**：两种输入都做，RGB888/BGR888 走旁路，YUYV 做转换。色彩矩阵做成可配。首版不做 MJPG，不做放大，不做 2 像素/拍。
2. **时钟**：用 clk_pl_0，100 MHz，与融合核、检测后处理核同在一个时钟域。
3. **预算**：以 OOC 布局布线后的实数为准。HLS 报告的 LUT 估计偏大约 2.3 倍，不能作为判据。
   - LUT：目标 ≤3,500，上限 4,500
   - DSP：≤20
   - RAMB36：≤6
   - URAM：0
   - 超出预算时，要写清楚超出多少、为什么。
4. **II 要求**：主循环 II=1，即 1 像素/拍。
   - 设计 R5 已指出难点：行缓冲同址先读后写、条件产出、齿轮箱放在同一个 dataflow 里。
   - 做不到 II=1 时，先用 `fpga-hls` skill 诊断根因并尝试修。
   - 实在不行可以降到 2 拍/像素，但要报出根因。
5. **接口**：
   - 控制口是 s_axilite。寄存器顺序按设计 §4.2 排；最终偏移以 HLS 生成为准，生成后回填进 README。
   - 数据口是一个 128 位 m_axi，读写都要，按 4 KB 对齐突发。
   - slot 11、irq bit 6 只是暂定，留到整板合入时与检测后处理核一起定。本包不改整板设计。
6. **缓存一致性**：核每帧必须连灰边一起写满整块张量。这是设计 §2.4 定下的不变量，不能为了省拍数去掉。
7. **测试只做关键几项**（owner 11-03：每个模块只做关键、必要的测试，时间留给设计和优化）：
   - **csim**：对参考逐字节一致，即 0 字节差。用例如下：
     - 设计 §3.2 列的真实图，每种配置至少 3 张；
     - **随机噪声图每种配置至少 2 张**。PREP0 的阴性对照在真实图上有 4/44 组没抓到 +1 LSB 的系数变异，所以必须有随机图；
     - 5 种目标配置都要覆盖：方 640、方 512、方 416、矩 640×480、矩 512×384；
     - YUYV 输入至少 1 组，对照 C 模型的 YUYV 路径。
   - **阳性对照**：故意改一个系数 +1，确认 csim 能报差。这一项只做一次。
   - **联仿（cosim）**：做 2 组，方 512 一组、YUYV 一组。确认逐字节一致，并读出实际拍数，与设计 §2.2 的手算拍数对照。
   - **OOC 布局布线**：在 xck26 上、10 ns 约束下拿 LUT、FF、DSP、BRAM 和 WNS。
   - 不做板测，不做整板构建。
