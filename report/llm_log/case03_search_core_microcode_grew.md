> - 非流水体里的宽乘法很便宜（scan 里 37×36、37×18 乘法各 25 LUT），**超支在加法/比较/移位表达式和多路选择**，不是乘法。
> - 每项都超手算 1.5 倍以上（brief 第 3 步：先改再 OOC）。HLS 估计一般高于 OOC（MEMK4 2,201 → 1,487），但这里差 2.5 倍，不能指望 OOC 收回。

## 3. 纠错过程

- **观测：** 记忆核微程序化把 LUT 降了 84%（案例 1），但同样的做法搬到搜索核上，第一版 csynth 估计 10,485 LUT，比要替代的 c8（OOC 9,683）还大，是手算的约 2.6 倍。
- **定位：** 执行代理逐部件对手算，指出超支不在乘法，而在两个专用单元（射线扫描、信念更新）和顺序器的多路选择——搜索核需要保留硬件专用单元，单元与顺序器共用存储口带来大量选择逻辑；这是记忆核没有的结构，所以不能直接套用记忆核的经验数字。
- **主会话的处理：** 不接受"OOC 会自己降回来"的期望（代理自己也写明差 2.5 倍不能指望 OOC 收回），按"超 1.5 倍先改"的规矩派第二棒，任务书（`briefs/srchk6_brief_r2.md`）写明先退回 c8 的 m_axi 写法验证 BRAM、再按交接 §4 逐项压，并给出中间门：

> 3. LUT 降到 ≤6,000（csynth）之后，跑联仿……
> 5. ……不过门：写清最好一版的 LUT 和拍数，交主控定。

## 4. 最终结果（截至本记录写作时）

- 功能：微程序版 m1 与 c8 C 模型逐字节相同（V1 32/32、V2 39/39），改一条微指令后 V1 有 7 条记录不一致，阳性对照成立（SRCHK6/README.md）。
- 面积：第二棒把微程序版压到 OOC 5,049 LUT（对 c8 的 9,683 LUT 降 47.9%），联仿 71/71 逐位一致，观测最长 0.82 ms、选点最长 1.22 ms；源码与报告见代码包 `hw/srch_v2/`。
- 教训：一种架构改写在一个核上成功，不代表在另一个核上成立；先 csynth 逐部件对手算，再决定是否继续投入。
