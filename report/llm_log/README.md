# 大模型协作记录（report/llm_log/）

本目录按大赛选题指南的要求，提交本作品开发过程中与大模型的交互记录：**提示词、模型回答、自我纠错轨迹**。全部内容摘自开发期间真实留存的任务书、报告与验收日志，只做了删节与脱敏，没有改写原意，也没有为展示补写。

## 1. 协作方式

开发采用"主会话 ＋ 执行型子代理"两层结构，模型为 Claude（Anthropic）：

- **主会话**负责方案设计、任务拆分、验收与判读：决定每个硬件核的预算与验收门（LUT、BRAM、时序、拍数、功能逐位一致），读回执行代理的报告与原始产物，判"收 / 部分收 / 不收"，并决定下一步。
- **执行型子代理**按书面任务书（brief.md）干活：写 HLS / C++ / Python 代码，跑 csim、csynth、联仿、OOC 与整板构建，上板测量，最后写 README.md（结论与数据）或 HANDOVER.md（交接）。
- **每个任务都有书面任务书和验收记录。** 任务书写明背景、要读的文件、步骤、验收门、纪律（例如判据先写后测、只按进程号停进程、不擅自降级）；验收记录逐条追加在主会话的验收日志里，只追加、不回改。
- **上下文到预算就轮换交接。** 一个执行代理的上下文用到约 20 万 token 就停手写 HANDOVER.md，由新代理带新任务书接着做（日志中"轮换"记录 37 处）。这样避免长上下文下质量下降。
- **自我纠错的三个来源：** ①执行代理按预注册判据如实报"不过"，并做区分性实验找原因；②主会话验收时用原始产物复核代理的结论，推翻不成立的推断；③主会话自己的估计（帧率、根因、时间）被实测推翻时，追加更正并回报。
